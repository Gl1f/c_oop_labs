# Матрица — лабораторная №2

Продолжение первой лабораторной по ООП на C++. Теперь одновременно работают несколько линий. Частота появления, скорость, длина и режим цветов задаются при запуске.

Номер по списку: **11**, первая половина группы. Форма — ромб, направление — слева направо. В режиме `N` символы зелёные, в режиме `Y` каждый новый символ получает случайный цвет.

## Запуск

Готовая программа находится в `build\matrix.exe`:

```bat
build\matrix.exe 3 23 8 Y
build\matrix.exe 1 10 15 N
build\matrix.exe
build\matrix.exe --help
build\matrix.exe /?
```

Порядок параметров: **частота появления, скорость, длина, Y/N**. Первые три значения — целые числа от 1 до 30. Скорость измеряется в символах в секунду, частота — в линиях в секунду. Без аргументов начинается последовательный ввод с повтором при ошибке. Выход — Esc.

## Что изменилось после первой работы

Раньше следующая линия запускалась после завершения предыдущей. Теперь менеджер в начале каждой секунды выбирает заданное количество случайных смещений от 0 до 1000 мс и сортирует их. Это моменты рождения, отсчитанные от начала секунды, а не задержки между линиями. Например, значения 200, 700, 400 дают старты на 200, 400 и 700 мс.

Совпадающие моменты допустимы. Смещение 1000 мс относится к предыдущей секунде планирования; в этот же момент может родиться линия нового плана со смещением 0. Поэтому на общей границе двух секунд возможны одновременные старты. План содержит ровно заданное число линий на каждую секунду. Фактическая точность вывода зависит от Windows и нагрузки.

Каждая линия хранит своё время рождения и скорость. Общий цикл проверяет время и обновляет все линии без дополнительных потоков. Если цикл задержался, просроченные появления и шаги не теряются. Закончившиеся линии удаляются.

Символы сохраняют свои координаты и цвет. Движение по-прежнему получается добавлением головы и удалением хвоста через кольцевой массив. Длина считается в символах; при появлении и уходе видна только часть линии.

Общий кадр собирается в памяти и выводится одним вызовом WinAPI. Это нужно для пересечений: стирание хвоста одной линии не оставляет дырку в другой. В общей клетке виден символ линии, нарисованной последней, а после её ухода снова видна оставшаяся линия.

## Классы

- `Application`: проверка параметров, расписание появлений, список активных линий.
- `Line`: собственная скорость и время старта, ромб, голова и хвост.
- `Symbol`: знак, координаты, цвет и видимость.
- `Console`: ввод, размеры окна, кадр, работа с WinAPI, ожидание и Esc.

Активные линии хранятся в `std::vector<std::unique_ptr<Line>>`. Вектор позволяет добавлять и удалять линии, а `unique_ptr` автоматически удаляет объект при удалении из списка. Внутри линии массив символов выделяется через `new[]` и освобождается через `delete[]`. Копирование линии запрещено.

Размер окна запоминается перед анимацией. После изменения размера программу нужно перезапустить. Для ромба нужна высота минимум 3 строки. При большом числе линий часть символов перекрывается; количество видимых ромбов не равно количеству запущенных линий.

## Сборка

Windows, C++11 и MinGW-w64 либо Visual Studio с поддержкой C++. CMake — дополнительный способ сборки.

Для MinGW добавить папку `bin` компилятора в `PATH`, затем запустить `build.bat`. Если компилятор уже доступен в терминале:

```bat
g++ -std=c++11 -Wall -Wextra -pedantic src\main.cpp src\Application.cpp src\Console.cpp src\Line.cpp src\Symbol.cpp -o matrix.exe -luser32 -static
```

Через CMake в терминале с настроенным компилятором:

```bat
cmake -S . -B build
cmake --build build --config Release
```

MinGW создаёт `build\matrix.exe`, Visual Studio — `build\Release\matrix.exe`.

## Проверка вручную

1. Открыть оба варианта справки.
2. Проверить ввод без аргументов и запуск `3 23 8 Y`.
3. Проверить границы 1 и 30 для всех трёх чисел.
4. Передать 0, 31, буквы, дробь, неверный флаг и неверное количество параметров.
5. Сравнить частоту 1 и 30. Убедиться, что новая линия появляется до завершения старой.
6. Сравнить режимы N и Y, дождаться ухода хвостов и нажать Esc.
